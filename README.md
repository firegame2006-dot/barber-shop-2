# MONARCH — Barbershop

Сайт барбершопу з онлайн-записом, магазином і адмін-панеллю.
Написаний **без фреймворків і без збірки** — це набір статичних файлів, які
можна відкрити напряму, а дані живуть у Supabase.

**Демо:** https://magnificent-nougat-9a4639.netlify.app

---

## Що вміє

**Клієнтська частина**

- Запис онлайн — послуга, майстер, дата, час, коментар; заявка одразу лягає в базу
- Магазин на 12 позицій з фільтром за категоріями
- Кошик: кількість, видалення, підрахунок, збереження між сесіями
- Оформлення: самовивіз або доставка, три способи оплати, валідація телефону
  для 10 країн
- «Замовити» окремою позицією, не чіпаючи кошик
- Дві мови (UA / EN) з перемиканням без перезавантаження
- Галерея з лайтбоксом, відгуки, контакти, живий індикатор «відчинено / зачинено»

**Адмін-панель** (`/admin`)

- Записи — пошук, фільтри за датою й статусом, зміна статусу, видалення
- Замовлення — склад, адреса доставки, коментар клієнта, шість станів
- Барбери, галерея, послуги, товари — повний CRUD із завантаженням фото
- Двомовне редагування: англійське поле можна лишити порожнім, підставиться
  українське

## Технології

| | |
|---|---|
| Фронтенд | HTML, CSS, JavaScript (ES5-сумісний, без залежностей) |
| Бекенд | Supabase — PostgreSQL, Auth, Storage |
| Доступ до даних | PostgREST через `fetch`; в адмінці — `@supabase/supabase-js` з CDN заради Auth |
| Хостинг | Netlify |
| Генерація сторінок | Python-скрипт, без npm і без node_modules |

Чому без фреймворку: сайт — це вітрина барбершопу на кілька сторінок.
React або Vue додали б збірку, залежності й крок деплою, не давши натомість
нічого, чого тут бракує. Ціна рішення — ручна робота з DOM; вона окупається
тим, що весь сайт вантажиться двома файлами.

### Як влаштований `script.js`

Один IIFE, поділений на пронумеровані розділи — від даних і перекладів до
кошика, оформлення й навігації. Дані (`SERVICES`, `BARBERS`, `GALLERY`,
`PRODUCTS`) оголошені зверху як запасний варіант: при старті вони
перезаписуються тим, що прийшло з Supabase, а якщо запит не пройшов —
сторінка малює те, що є в файлі, і ніколи не лишається порожньою.

### Генерація сторінок

П'ять внутрішніх сторінок не редагуються руками. Хедер, футер, кошик і всі
модальні вікна беруться з `index.html`, тож розійтися вони не можуть:

```bash
python .claude/build_pages.py
```

Скрипт заразом рахує відбиток `style.css` і `script.js` та вписує його в
адреси файлів (`script.js?v=01b361ca`). Це прибиває кешування намертво:
змінився файл — змінилась адреса — браузер зобов'язаний завантажити наново.
Запускати після кожної зміни в цих двох файлах.

## Запуск

Сайт статичний, збірка не потрібна.

```bash
python .claude/devserver.py 5173
```

Потім `http://localhost:5173`. Сервер віддає файли з `no-store`, щоб під час
роботи не ловити старі версії.

Можна відкрити `index.html` і просто з диска — тоді Supabase буде недоступний
(`file://` блокує запити), і сайт покаже дані, зашиті в `script.js`.

## Адмін-панель

Відкривається на `/admin`. Доступ дає **не сторінка, а база**: кожна таблиця
відмовляє в читанні й записі, якщо `auth.uid()` немає в таблиці `admins`.
Тобто навіть обійшовши перевірку в браузері, сторонній не отримає жодного
рядка.

Щоб завести адміністратора — див. [docs/supabase.md](docs/supabase.md).

### Про ключ у коді

`sb_publishable_…` видно кожному, хто відкриє сторінку, і так задумано: цей
ключ **називає проєкт**, а не дає прав. Усе вирішують політики RLS.
`service_role` у клієнтському коді не використовується ніде, `.env` не
потрібен.

Публічний ключ уміє рівно дві речі: створити заявку на запис або замовлення,
і прочитати те, що й так намальовано на сайті. Читати чужі записи, змінювати
статуси чи видаляти — ні.

### Суми замовлень

Ціни лежать у таблиці `products`, і тригер перераховує кожну суму при вставці.
Те, що надіслав браузер, зберігається окремо в `client_total`, але ніколи не
використовується — підмінити суму через DevTools не вийде.

## Кілька рішень, які варто пояснити

**Двомовність через словник, а не через окремі сторінки.** Кожен елемент
із `data-i18n` бере текст зі словника в `script.js`; перемикання не
перезавантажує сторінку і не подвоює кількість файлів.

**Мобільна версія — не звужений десктоп.** На телефоні довгі секції головної
замінені плиткою розділів, а самі розділи відкриваються окремими сторінками.
Запис і контакти стають попапами.

**Товар можна замовити, не чіпаючи кошик.** «Замовити» відкриває оформлення
для однієї позиції; кошик при цьому не очищається й не поповнюється.

**Заявка не губиться при збої мережі.** Якщо запит не пройшов, копія лягає в
`localStorage`, а клієнт бачить чесне повідомлення про невдачу — не фальшиве
«дякуємо». Автоматичного повтору немає навмисно: невдалий запит міг усе ж
дійти до бази, і дубль створив би більше проблем, ніж вирішив.
