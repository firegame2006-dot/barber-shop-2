# Supabase — таблиця `appointments`

Форма запису на сайті пише напряму в таблицю `appointments` через PostgREST.
Бібліотеки немає: один `fetch` у `script.js`, сайт лишається набором статичних
файлів без збірки.

Налаштування — у `script.js`, константа `SUPABASE` (URL, ключ, назва таблиці).

---

## Ключ у коді — це нормально

`sb_publishable_…` видно кожному, хто відкриє сторінку. Так і задумано: цей
ключ **лише називає проєкт**, він нічого не дозволяє сам по собі. Усе, що
відвідувач може зробити з таблицею, вирішують політики RLS.

Тобто безпека тут не в тому, щоб сховати ключ, а в тому, щоб політики були
правильні.

---

## Що потрібно зробити (обов'язково)

Зараз RLS увімкнено, але **політики на вставку немає**, тож форма отримує
помилку `42501` і нічого не зберігає. Перевірено запитом до бази.

Відкрийте **Supabase → SQL Editor** і виконайте:

```sql
create policy "anon can request an appointment"
  on public.appointments
  for insert
  to anon
  with check (
    status = 'pending'
    and char_length(name) between 2 and 80
    and char_length(phone) between 7 and 20
    and date >= current_date
  );
```

Чому саме так, а не просто `with check (true)`:

| Умова | Що вона зупиняє |
|---|---|
| `status = 'pending'` | відвідувач не може створити собі одразу підтверджений запис |
| межі довжини | сміттєві рядки на кілограм тексту |
| `date >= current_date` | записи «заднім числом» |

**Політику на читання не додавайте.** Її відсутність — це і є захист: у таблиці
імена й телефони клієнтів, і публічний ключ не повинен їх віддавати. Читати
записи ви будете через панель Supabase, де працюєте під своїм акаунтом.

---

## Перевірка після додавання політики

```bash
curl -i -X POST "https://mvnmnhtcgbgpbocjafqz.supabase.co/rest/v1/appointments" \
  -H "apikey: sb_publishable_f8cgj01CBVrdHXrfAPiarA_RZzHC5VD" \
  -H "Authorization: Bearer sb_publishable_f8cgj01CBVrdHXrfAPiarA_RZzHC5VD" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "Prefer: return=minimal" \
  --data-binary '{"name":"Test","phone":"+380670000000","service":"Test","date":"2026-12-31","time":"12:00","status":"pending"}'
```

- `201` — працює.
- `401` + `42501` — політика ще не застосувалась.

А тоді спробуйте прочитати:

```bash
curl -s "https://mvnmnhtcgbgpbocjafqz.supabase.co/rest/v1/appointments?select=*" \
  -H "apikey: sb_publishable_f8cgj01CBVrdHXrfAPiarA_RZzHC5VD" \
  -H "Authorization: Bearer sb_publishable_f8cgj01CBVrdHXrfAPiarA_RZzHC5VD"
```

Має повернутись `[]` навіть коли в таблиці є записи. Якщо повертає рядки —
десь є зайва політика на `select`, її треба прибрати.

## Як лягають поля

| Поле форми | Колонка | Приклад |
|---|---|---|
| Ім'я | `name` | `Тарас` |
| Телефон + код країни | `phone` | `+380671112233` |
| Послуга | `service` | `Класична стрижка` |
| Дата | `date` | `2026-08-21` |
| Час | `time` | `12:00` |
| — | `status` | `pending` |
| — | `id`, `created_at` | ставить сама база |

У колонку `service` пишеться **назва** послуги, а не її внутрішній код, і завжди
українською — щоб таблиця читалася однаково незалежно від того, якою мовою
користувався клієнт.

`status` починається з `pending`: адміністратор спершу телефонує і лише потім
переводить запис далі. Ті самі стани, що й у замовленнях магазину.

---

## Два поля, яким немає куди лягти

Форма збирає ще **майстра** і **коментар**, а колонок під них у таблиці немає.
Зараз вони просто не надсилаються.

Якщо потрібні — виконайте:

```sql
alter table public.appointments
  add column barber text,
  add column note   text;
```

І скажіть — я допишу їх у запит. Без цього кроку додавати їх не можна: PostgREST
відхилить запит із невідомою колонкою, і форма перестане працювати зовсім.

---

## Якщо запит не пройшов

Заявка не губиться: копія лягає в `localStorage` під ключем
`monarch_bookings_failed` разом із текстом помилки. Клієнт при цьому бачить
чесне повідомлення про невдачу, а не фальшиве «дякуємо».

Автоматично такі заявки **не пересилаються**. Невдалий запит міг усе ж дійти до
бази, і повтор створив би дубль. Це резерв для відновлення вручну, а не черга.
Якщо хочете автоматичну повторну відправку — скажіть, зроблю разом із захистом
від дублів.
